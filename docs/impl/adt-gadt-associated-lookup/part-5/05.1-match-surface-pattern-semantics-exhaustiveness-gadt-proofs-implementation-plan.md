# Phalcom Part 05.1 Match Semantics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement Phalcom's statically total `match` expression and formal recursive pattern semantics through stable `phalcom-semantic` match-resolution products, including wildcard, or-patterns, selector/family variant patterns, unions, exhaustiveness, and GADT branch proofs.

**Architecture:** `phalcom-ast` owns syntax only. `phalcom-semantic` resolves every variant/family pattern to exact semantic candidates, constructs a value-space model independent of ordinary `TypeId` narrowing, solves GADT compatibility, computes usefulness/residual coverage, proves totality, and publishes a `MatchResolutionIndex` on each `CallableAnalysis`. Part 05.1 does not modify executable lowering in `phalcom-core`; Part 05.2 consumes the published products and realizes them with Part-04 runtime primitives.

**Tech Stack:** Rust 2024, `phalcom-ast` hand-written lexer/parser, `phalcom-common::selector::{Selector, SelectorPattern}`, `phalcom-semantic`, canonical `TypeStore`, `CaseTypeEnvironment`, semantic explanation DAG, Cargo integration tests.

**Spec:** `docs/impl/adt-gadt-associated-lookup/part-5.1/05.1-match-surface-pattern-semantics-exhaustiveness-gadt-proofs-technical-spec.md`

**Verified baseline:** `feat/adts@c184fb85212d8555f49821a01d81864b3a161cfa` (`test: add ADT associated-family conformance suite`)

## Global Constraints

- Every accepted `match` must be statically exhaustive. There is no ordinary partial match and no user-level `MatchError` path.
- `match` is an expression and `=>` is dedicated match-arm syntax.
- `_` is a first-class recursive wildcard that binds nothing.
- `Animal::Dog`, `Animal::Dog()`, exact callable selectors, `Animal::Dog(...)`, partial selector patterns such as `Animal::Dog(x, ..., named: y)`, and `Animal::Dog*` remain semantically distinct.
- Exact callable variant patterns must specify every selector field; `...` is the only selector-pattern mechanism that intentionally omits an arbitrary middle span.
- Labeled payload patterns use external selector labels and map to `VariantFieldId`.
- Contextual shorthand resolves from the expected pattern domain; it is not global constructor lookup.
- Or-pattern alternatives must bind the same names; binding types join; only common proof facts survive into the shared branch.
- Union types, including transparent alias-defined unions, participate directly in coverage.
- GADT case reachability is constraint compatibility, not ordinary subtype filtering.
- Successful case analysis introduces exact-case evidence and declaration-owned case equalities only inside the branch where they are proven.
- Inaccessible reachable variants still participate in exhaustiveness. Construction visibility does not control matching.
- `PatternSpace`/coverage state is semantic proof machinery and must not be forced into ordinary `FlowState`/`TypeId` when precision would be lost.
- The existing `SelectorPattern::matches` implementation is the authority for selector-gap compatibility. Do not implement a second selector matcher in match code.
- `phalcom-semantic` remains the sole static semantic authority. Part 05.2 must be able to lower from 5.1 products without source-name or family rediscovery.
- Do not edit `phalcom-core` execution/lowering as part of Part 05.1.
- Guards remain deferred.
