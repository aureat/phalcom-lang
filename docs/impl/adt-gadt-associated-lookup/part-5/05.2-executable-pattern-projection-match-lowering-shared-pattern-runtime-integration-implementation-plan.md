# Phalcom ADT/GADT + Associated Lookup
## Part 05.2 — Executable Pattern Projection, Match Lowering, Shared Pattern Runtime Integration, and Elimination Completion
### Repository-Grounded Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to execute this plan task-by-task. Use test-driven development for every behavioral task. Before claiming completion, run the full verification matrix in Task 18 and report the actual command outputs/failures.

**Goal:** Consume Part 05.1's formal pattern/match semantic products without reinterpreting source syntax, project them into compact executable pattern specifications, lower `match` and all existing pattern-consuming control/binding contexts through one staged-binding compiler engine, execute exact ADT case tests through Part-04 `IsVariant` / `GetVariantPayload`, preserve the current immediate core `Option` representation through a typed runtime compatibility bridge, and retire legacy source-string/class-based ADT matching.

**Architecture:** `phalcom-semantic` remains the sole authority for variant/family resolution, contextual shorthand, GADT reachability, binding joins, usefulness, and exhaustiveness. `phalcom-core/src/modules/semantic_lowering.rs` converts semantic identities to backend execution facts such as exact `VariantId` targets and physical payload slots. The AST compiler consumes only those frozen facts, uses one recursive staged pattern emitter, and emits ordinary jumps plus the Part-04 case bytecodes. The VM does not interpret patterns and does not solve GADT constraints.

# 0. Hard Invariants

Do not begin implementation without internalizing these rules:

- [ ] `phalcom-semantic` is the only source-level pattern semantic authority.
- [ ] Part 05.2 must not resolve a variant from a source string.
- [ ] Part 05.2 must not expand a selector/family pattern from source syntax.
- [ ] Part 05.2 must not solve GADT equalities.
- [ ] Part 05.2 must not recompute usefulness or exhaustiveness.
- [ ] Part 05.2 must not use `.class` equality for general ADT case identity.
- [ ] Part 05.2 must not use `isSome` / `isNone` as the general ADT pattern model.
- [ ] Every accepted ordinary `match` remains statically total; no user-level `MatchError` is introduced.
- [ ] The match scrutinee evaluates exactly once.
- [ ] `while let` RHS evaluates exactly once per iteration.
- [ ] Failed refutable patterns and failed or alternatives commit no user-visible bindings.
- [ ] Braced match arms execute inline in the current callable; they do not produce closure values.
- [ ] GADT proof state remains erased at runtime.
- [ ] Selector/family patterns are statically expanded to exact case candidates; no runtime pattern-family object is introduced.
- [ ] Initial lowering uses straightforward ordered exact-case tests. Jump tables / DAG factoring / shared-prefix factoring remain deferred backend optimization work.

# Deferred Match Backend Optimization Backlog

The following are explicitly deferred from Part 05.2 correctness work:

- **Variant jump tables** — dispatch directly from a runtime discriminant/case index for large closed candidate sets instead of repeated `IsVariant` instructions.
- **Decision DAG factoring** — share overlapping tests and payload projections across arms/or alternatives.
- **Shared-prefix factoring** — test a common prefix such as `Some(...)` once before nested alternatives like `Ok` / `Error`.
- **Payload extraction reuse** — retain one extracted field when multiple downstream tests consume it.
- **Candidate-set compression** — lower large family patterns more compactly when the backend has a suitable exact-case set primitive.

These are backend transformations over already-frozen semantic products. They must never introduce source-level variant/family resolution, GADT solving, or exhaustiveness reasoning into `phalcom-core`.
