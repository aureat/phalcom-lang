## 1. Goal

Materially reduce corpus and semantic test wall-clock time by eliminating
repeated cold Universe construction — semantic session startup, compiler
session setup, and VM bootstrap — that currently constitutes the dominant
fraction of per-fixture cost.

---

## 2. Checkpoint acceptance objective

This plan is the first implementation plan for `PERF003.C1`
(performance instrumentation and test harness performance).

It is *not* checkpoint closure. Its deliverables are:

1. A functioning timing/counter instrumentation layer that gives exact
   per-phase attribution for every test fixture.
2. Fixes for correctness issues found during the audit (stale `scripts/test.sh`
   targets; `corpus::blocks` baseline classification).
3. A process-shared canonical semantic Universe baseline
   (`CanonicalUniverseSemanticBaseline`) that eliminates per-session Universe
   reconstruction in `phalcom-semantic`.
4. A persistent `ProgramCompilationSession` that eliminates full session
   teardown between corpus fixtures.
5. A purpose-built `BootstrappedRuntimeImage` that eliminates per-fixture
   Universe VM bootstrap.

Later checkpoints (PERF003.C2 onward) own per-fixture harness granularity,
relocatable compiled Universe artifacts, and production CLI startup improvement.

## 7. Architecture invariants

The following must hold after every task:

**A1.** `SemanticWorkspaceSession::new()` must produce semantically equivalent
output before and after T4. No test that was previously passing may begin
failing.

**A2.** `CanonicalUniverseSemanticBaseline` (new) must be process-wide and
initialized at most once per process. No test may construct the baseline more
than once.

**A3.** A `TypeStore` forked from the canonical prefix must have a distinct
`TypeStoreId` from the baseline. IDs allocated within the canonical prefix
must be numerically identical across all forks. New workspace-local IDs must
not collide with canonical prefix IDs.

**A4.** `VM::from_bootstrap_image()` must produce VMs whose observable
execution output is identical to `VM::new()` for every corpus fixture.

**A5.** No mutable VM state may be shared between two `VM` instances produced
from the same `BootstrappedRuntimeImage`. Mutation in instance A must not
affect instance B.

**A6.** A `ProgramCompilationSession` must not allow fixture A's declarations
to be visible in fixture B. Module identity replaces rather than accumulates.

**A7.** All existing `cargo test` invocations that are currently green must
remain green. No green test may be broken.

**A8.** `VM::new()` must remain the production path and must not be altered in
observable semantics.

### T2 — Cache `canonical_universe_linked_program` in `phalcom-semantic`

**Scope:** A smaller standalone win that is a prerequisite for T4.

Currently `phalcom-semantic/src/session.rs` calls into module/link machinery
to build a fresh `LinkedProgram` for every new semantic session. This is
separate from (and does not benefit from) the `CanonicalUniverseProgram`
`OnceLock` in `phalcom-core`, because the semantic crate does its own
discovery and linking.

Add a process-level cache in `phalcom-semantic`:

```rust
// phalcom-semantic/src/session.rs  (or a new canonical_baseline.rs)

static CANONICAL_LINKED_UNIVERSE: OnceLock<Arc<LinkedProgram>> = OnceLock::new();

fn canonical_universe_linked_program_cached() -> Arc<LinkedProgram> {
    Arc::clone(CANONICAL_LINKED_UNIVERSE.get_or_init(|| {
        Arc::new(build_canonical_universe_linked_program())
    }))
}
```

Where `build_canonical_universe_linked_program()` contains the current
discovery/link code for the default `UniverseSourceProvider`.

The existing `with_universe_source_provider(provider)` path — used for
hostile/custom-Universe tests — must remain uncached:

```rust
fn linked_universe_for(provider: &UniverseSourceProvider) -> Arc<LinkedProgram> {
    if provider.is_canonical() {
        canonical_universe_linked_program_cached()
    } else {
        Arc::new(build_linked_program_for(provider))
    }
}
```

`UniverseSourceProvider` needs an `is_canonical()` predicate if it does not
already have one. Adding it is the only required API change.

### T3 — `TypeStore` fork/lineage

**Scope:** Introduce an explicit fork operation on `TypeStore` that establishes
a fresh `TypeStoreId` while preserving all canonical-prefix node IDs.

This is a prerequisite for T4 because T4 clones the baseline `TypeStore` into
per-session forks. Without explicit fork semantics, two forks would share a
`TypeStoreId`, which conflicts with `StoreQualifiedTypeId` and `SemanticSnapshotId`.

#### T3.1 — Fork operation

Add to `TypeStore`:

```rust
impl TypeStore {
    /// Create a fork from a canonical prefix.
    ///
    /// All node IDs allocated in `self` are preserved with identical numeric
    /// values in the fork. The fork receives a fresh `TypeStoreId` so that
    /// type references qualified by store identity remain unambiguous.
    ///
    /// The fork starts fully independent: mutations to the fork do not affect
    /// `self` or any other fork derived from `self`.
    pub fn fork_from_baseline(&self) -> Self {
        let mut fork = self.clone_internal_data();
        fork.id = TypeStoreId(NEXT_TYPE_STORE_ID.fetch_add(1, Ordering::Relaxed));
        fork
    }
}
```

`clone_internal_data()` is a private deep copy of the store's maps, interning
tables, and node storage — it must not copy the `id` field (which is
intentionally replaced).

**FIXED:** Node IDs in the canonical prefix must be numerically stable across
all forks. Two forks of the same baseline must have identical canonical-prefix
nodes at the same IDs.

**MECHANICALLY FLEXIBLE:** The exact internal clone strategy (field-by-field,
`#[derive(Clone)]` on a helper, manual), as long as it is a deep independent
copy.

#### T3.2 — Lineage marker (optional hardening)

If P2's `StaticValueStore` work makes store lineage-qualified references
important, add a `TypeStoreLineageId` that both baseline and all its forks
share, distinct from the per-fork `TypeStoreId`. This is **optional for P1** of
this plan but is the preferred mature form:

```rust
pub struct TypeStore {
    store_id:   TypeStoreId,    // unique per store/fork
    lineage_id: TypeStoreLineageId, // shared across baseline and all its forks
    ...
}
```

Decision: implement lineage only if LANG007.C4.P3 or later explicitly requires
store-qualified lineage checks. Do not add it speculatively.

**Verification (T3):** Add a unit test in `phalcom-semantic`:

```rust
#[test]
fn forked_stores_have_distinct_ids_and_identical_prefix() {
    let baseline_store = build_test_baseline_store();
    let fork_a = baseline_store.fork_from_baseline();
    let fork_b = baseline_store.fork_from_baseline();

    assert_ne!(baseline_store.id(), fork_a.id());
    assert_ne!(fork_a.id(), fork_b.id());

    // Canonical prefix node lookup must agree.
    let canonical_id = baseline_store.some_canonical_node_id();
    assert_eq!(fork_a.node(canonical_id), baseline_store.node(canonical_id));
    assert_eq!(fork_b.node(canonical_id), baseline_store.node(canonical_id));
}
```

### T5 — `ProgramCompilationSession`

**Scope:** Introduce a reusable compilation session that retains the incremental
semantic workspace and module session between corpus fixtures, applying only a
fixture-level source mutation per step.

#### T5.1 — API definition

```rust
// phalcom-core/src/compile/session.rs  (new, or phalcom-modules equivalent)

pub struct ProgramCompilationSession {
    module_session:    WorkspaceModuleSession,
    semantic_session:  SemanticWorkspaceSession,
    canonical_universe: Arc<CanonicalUniverseInputs>,
    generation:        u64,
    fixture_module_id: SourceFileId,   // stable identity for the "current fixture"
}

impl ProgramCompilationSession {
    /// Create a standalone session backed by the canonical Universe baseline.
    pub fn standalone() -> Result<Self, ProgramCompileError>;

    /// Replace the current fixture with `source` and compile it.
    ///
    /// The semantic session sees only the new fixture; prior fixture
    /// declarations are not visible.
    pub fn compile_fixture(
        &mut self,
        path: &Path,
        source: &str,
    ) -> Result<CompiledProgram, ProgramCompileError>;
}
```

#### T5.2 — Incremental fixture replacement

Each `compile_fixture` call must:

1. Increment `self.generation`.
2. Apply a module-level `SetOverlay` mutation that replaces the fixture
   source entirely (not appends):

   ```rust
   self.module_session.apply_module_mutations([
       WorkspaceSourceBatchMutation::SetOverlay {
           source: self.fixture_module_id,
           text: source.to_owned(),
           revision: self.generation,
       }
   ]);
   ```

3. Publish the module update.
4. Call `self.semantic_session.update(...)` with the module update.
5. Compile from the resulting snapshot.

The canonical Universe modules are never mutated; only the fixture module
changes between calls.

#### T5.3 — Isolation invariant

A fixture's declarations must not survive to the next fixture.

Implement a hostile regression test (see §9 Regression tests, R3 and R4).
This test must be added before T5 is considered complete.

**FIXED:** Module identity is stable across fixtures; its *source* is replaced.

#### T5.4 — Corpus harness integration

from:

```rust

fn run_corpus_dir(group: &str) {
    let mut session = ProgramCompilationSession::standalone()
```

### T7 — `BootstrappedRuntimeImage`

**Scope:** Create a purpose-built frozen representation of a fully bootstrapped
VM, and use it to eliminate per-fixture Universe compilation and execution.

This is the most invasive task. It must follow G1 (T4) and G2 (T5).

#### T7.1 — `HeapImage` — an independently cloneable heap snapshot

`Heap` is not currently `Clone`. Introduce:

```rust
// phalcom-core/src/vm/heap.rs  (or adjacent)

pub(crate) struct HeapImage {
    // Deep copy of bootstrap-phase heap contents.
    // Slotmap keys must be preserved identically.
    objects: ...,
    product_layouts: ...,
    // ... other heap backing fields
}

impl HeapImage {
    /// Instantiate a fresh independent heap from this image.
    pub(crate) fn instantiate(&self) -> Heap { ... }
}
```

`instantiate()` must copy without key reassignment: `ObjRef(57)` in the image
must correspond to `ObjRef(57)` in every instantiated heap.

**FIXED:** Keys must be numerically stable. This is the invariant that makes
the approach sound (see §11 of the audit document).

#### T7.2 — Identify the image boundary

The image captures **persistent canonical runtime state** that is safe to
copy without re-execution:

```text
INCLUDE in image:
  HeapImage (bootstrapped objects)
  Universe handles
  module registry
  runtime typing metadata
  class / layout maps
  interned symbol tables
  canonical runtime roots
  ADT / data registries
  product descriptors / layouts
  canonical dispatch state
  semantic roots

DO NOT include in image:
  operand stack
  call stack
  control stack
  active fibers
  open upvalues
  scheduler queue
  reactor
  output sink
  pending failures
  runtime execution caches
  temporary native state
  per-run counters
```

The exact field mapping is **VERIFY-FIRST**: read `VM`'s field list in
`phalcom-core/src/vm/` and classify each field into the correct bucket.

#### T7.3 — `BootstrappedRuntimeImage` struct

```rust
pub struct BootstrappedRuntimeImage {
    heap:             HeapImage,
    universe:         Universe,
    interner:         InternerImage,
    module_registry:  ModuleRegistryImage,
    typing_registry:  RuntimeTypingRegistry,
    runtime_roots:    RuntimeRoots,
    semantic_roots:   SemanticRoots,
    class_layouts:    ...,
    // ... other persistent canonical registries
}
```

#### T7.4 — Freeze operation

```rust
impl VM {
    /// Freeze this VM's post-bootstrap state into a reusable image.
    ///
    /// Preconditions (checked; returns Err on violation):
    ///   - no active user frames
    ///   - root fiber idle
    ///   - no open upvalues
    ///   - no queued tasks
    ///   - no pending reactor resources
    ///   - canonical modules all initialized
    ///   - no failed modules

    pub fn freeze_bootstrap_image(
        self,
    ) -> Result<BootstrappedRuntimeImage, BootstrapImageError> { ... }
}
```

#### T7.5 — Process-shared image singleton

```rust
static TEST_VM_IMAGE: OnceLock<BootstrappedRuntimeImage> = OnceLock::new();

pub fn canonical_runtime_bootstrap_image() -> &'static BootstrappedRuntimeImage {
```

## 11. Escalation triggers

STOP AND CONSULT on any of:

1. `TypeStoreId` stability across forks cannot be maintained — canonical prefix
   node IDs change between forks.
2. `HeapImage` clone cannot preserve `ObjRef` key values — the soundness
   premise of the image approach fails.
3. A canonical mutable Universe object (class, module, method table) cannot
   be deep-copied without sharing live backing state.
4. Any corpus fixture that was previously passing now fails with altered
   observable output after T4/T5/T7.
5. Implementing `BootstrappedRuntimeImage` requires modifying `VM::new()`'s
   observable semantics.
6. The semantic baseline cloning approach would require introducing a second
   source of canonical semantic truth.
7. `ProgramCompilationSession`'s incremental approach requires changes to
   `SemanticWorkspaceSession::update()` that alter P2-established contracts.
8. The scope becomes materially larger than the four-task structure above.

Use `docs/workflow/shared-consultation-escalation-protocol.md`.
