# Established root cause

The runtime export-materialization architecture is already present.

The runtime has the conceptual pipeline:

```text
LinkedModuleInterface.exports
        ↓
materialize_linked_exports_for_module(...)
        ↓
RuntimeExportRef::Binding | RuntimeExportRef::Module
        ↓
ModuleObject.exports
```

Canonical Universe bootstrap also goes through the linked-read/export materialization seam.

Therefore, do **not** begin by adding another runtime export-materialization phase. Verify the current code first, but expect the runtime to be faithfully projecting the linked interface that it was given.

The failure originates earlier:

```text
canonical Universe source
        ↓
InterfaceBuilder
        ↓
declarations = { Selector, SelectorPattern }
exports      = {}
        ↓
ModuleLinker
        ↓
LinkedModuleInterface.exports = {}
        ↓
runtime materializer
        ↓
ModuleObject.exports = {}
        ↓
selector.Selector
    → Module.doesNotUnderstand

from ...selector import Selector
    → export lookup fails
```

`InterfaceBuilder` deliberately separates declarations from exports. A top-level declaration does not automatically become an export under the currently implemented module model; explicit source `export` statements populate `UnlinkedModuleInterface.exports`.

The canonical sources currently expose the defect directly.

Conceptually:

```phalcom
// universe/reflection/selector.ph

@native
class Selector is Object {
  ...
}

@native
class SelectorPattern is Object {
  ...
}

// No export declaration.
```

and:

```phalcom
// universe/reflection/message.ph

@native
class Message is Object {
  ...
}

// No export declaration.
```

Compare this with a canonical Universe source that already follows the implemented interface model:

```phalcom
const unsupported = Unsupported.instance

export unsupported
```

The REPL is therefore observing the correct result for the malformed/incomplete leaf interfaces.

# Important masking behavior

Do not be misled by tests such as:

```phalcom
from universe import PackageInfo
```

already succeeding.

`BuiltinInterfaceBuilder` has a deliberate Universe-root-only overlay. At the root, exported native bindings can be exposed as canonical-declaration façade exports.

That mechanism is why root convenience imports may work even when the owning leaf module has no corresponding explicit source export.

Conceptually:

```text
universe root
    └── synthetic/canonical façade export
        PackageInfo
            ↓
        universe.reflection.package_info::PackageInfo
```

This does **not** imply:

```text
universe.reflection.package_info
    automatically exports PackageInfo
```

and it must not be generalized into such a rule accidentally.

The root façade policy and a module's own public export policy are separate concerns.

# Architectural invariants to preserve

The implementation must preserve all of the following.

## 1. Source/module interfaces own public API

The authority chain is:

```text
source declaration/export syntax
        ↓
UnlinkedModuleInterface
        ↓
LinkedModuleInterface
        ↓
RuntimeExportRef
```

Runtime code consumes this information. It does not invent another export policy.

## 2. Native metadata is not module export authority

Native metadata may describe:

- native implementation association;
- bootstrap ownership;
- prelude policy;
- root façade policy where explicitly designed.

It must not become a blanket rule saying:

```text
@native declaration => exported from its leaf module
```

Do not auto-export every `UNIVERSE_BINDINGS` entry from its owning leaf module merely to fix these tests.

That would create two authorities for module API:

```text
source export syntax
vs.
native metadata
```

which is exactly what the canonical Universe architecture is intended to avoid.

## 3. Prelude membership is separate from export membership

Do not conflate:

```text
bare Selector availability
```

with:

```text
universe.reflection.selector exports Selector
```

and do not conflate either with the Universe-root façade.

These are different policies.

## 4. `expose` remains path visibility only

A package exposing a child module does not export the contents of that child.

Do not make this work:

```phalcom
from universe.reflection import Selector
```

unless `reflection` explicitly re-exports `Selector`.

Existing tests asserting that an exposed child or unexported symbol cannot be selectively imported must remain green.

## 5. Runtime module member lookup remains export-based

Do not fix:

```phalcom
selector.Selector
```

by changing `Module.doesNotUnderstand` to fall back to arbitrary module globals.

That would silently erase module encapsulation:

```text
private/local declaration
    becomes accessible
    merely because it has a runtime global slot
```

The member namespace of a module is its public export namespace.

## 6. Re-exports preserve canonical target identity

For an export:

```text
public module A
    export X
        ↓
actual owner module B::X
```

the runtime representation must remain capable of:

```text
RuntimeExportRef::Binding {
    module: B,
    slot: X
}
```

There is no requirement for `A` to manufacture its own local `X` slot.

The REPL selective-import consumer should continue consuming the actual `RuntimeExportRef`, not reconstructing a binding from the public name.
